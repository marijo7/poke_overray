# ポケモンチャンピオンズ 採用率オーバーレイ (OBS)

対戦画面に映っている**相手のポケモンを画面から読み取り**、そのポケモンの
**よく使われている技・持ち物・特性（採用率）**を OBS 上に表示するツールです。
**自分と相手のパーティ**もポケモンの画像つきで表示できます。

```
キャプチャボード → OBS ─(OBS WebSocket でスクショ取得)→ main.py
                                                         │ ① 名前の部分を切り出し
                                                         │ ② Windows 標準 OCR で文字認識
                                                         │ ③ 全ポケモン名とあいまい一致
                                                         │ ④ 採用率データ (data/usage.json) を検索
OBS ブラウザソース ← http://127.0.0.1:8765/overlay ←──┘
```

- 画面の文字認識は Windows 標準の機能を使います（使えない PC では自動で RapidOCR に切り替わります）。GPU は不要です
- OBS からスクリーンショットを受け取るので、キャプチャボードを OBS と取り合いません
- 読み取りに失敗しても、設定画面から手動でポケモンを切り替えられます

## 必要なもの

- Windows 10 / 11
- [Python 3.10 以降](https://www.python.org/downloads/)（インストール時に「Add python.exe to PATH」にチェック）
- OBS Studio 28 以降（WebSocket が標準搭載）
- Windows の日本語の文字認識（日本語版 Windows なら通常は入っています。下の「文字認識の確認」参照）
  - 日本語版 Windows なら通常は入っています

## セットアップ

1. このフォルダを好きな場所に置き、`setup.bat` をダブルクリック
   （仮想環境の作成・ライブラリのインストール・採用率データの取得を行います）
2. OBS で **ツール → WebSocket サーバー設定** を開き、「WebSocket サーバーを有効にする」をオン。
   「接続情報を表示」でパスワードを確認しておく
3. `start.bat` を一度起動して閉じると `config.json` ができるので、メモ帳で開いて次を書き換える

   ```json
   "obs": {
     "host": "localhost",
     "port": 4455,
     "password": "OBS の WebSocket パスワード",
     "source": "映像キャプチャデバイス",   ← ゲーム画面を映している OBS のソース名
     "width": 1920,
     "height": 1080
   },
   ```

4. もう一度 `start.bat` を起動

### 文字認識の確認

`check_ocr.bat` をダブルクリックすると、文字認識が使えるか確認できます（テスト画像の「ガブリアス」を読み取ります）。

- 「Windows の文字認識 … 日本語: 使えます」と出れば OK
- 使えない場合も、自動で **RapidOCR** に切り替わるので、そのまま使えます（初回起動時に認識モデルを自動でダウンロードします）
- Windows の文字認識を入れたい場合は、**管理者として実行した PowerShell** で次を実行します
  （Windows 11 の設定画面の「言語のオプション」には文字認識の項目が表示されないため）

  ```powershell
  # 入っているか確認 (State が Installed なら入っている)
  Get-WindowsCapability -Online | Where-Object Name -like 'Language.OCR*ja-JP*'
  # 入れる
  Add-WindowsCapability -Online -Name "Language.OCR~~~ja-JP~0.0.1.0"
  ```

## 使い方

### 1. 読み取り範囲を合わせる（最初の 1 回）

ブラウザで **http://127.0.0.1:8765/control** を開きます。

**まずは自動調整**: 選出画面を表示した状態で「読み取り範囲」の **「今の画面から自動で合わせる」** を押し、
対戦画面（自分と相手が 2 体ずつ出ている画面）でもう一度押します（それぞれ数秒〜十数秒）。
機種によって画面の端の余白や表示の大きさが違っても、画面の中の目印から範囲を合わせます。
押したあとは画像の枠が名前・顔・性別マークに合っているか確認し、ずれていれば下の手順で直してください。

- 目印: 選出画面は「選出してください」の文字・自分の名前の並び・相手の赤い枠、対戦画面は名前欄のパネルの形
- スマホ版 / Switch 版のどちらの画面かも自動で判断します
- 自動で合わせた（または手で直した）範囲は、別の配置への自動切り替えをしなくなります。
  初期値に戻すときは「この画面用の範囲にする」を押してください

手で合わせる場合:

- ゲーム画面が表示されるので、対戦中の画面にした状態で調整します
- 右下の「領域一覧」で領域を選び、画像上で**相手ポケモンの名前の文字**をドラッグで囲む
- ダブルバトルなら相手 2 体分（初期状態で `opp1` / `opp2` の 2 つ）、シングルなら 1 つにして「保存」
- 「現在の表示」に OCR の読み取り結果が出るので、正しく認識されているか確認できます

> 初期の範囲はスマホ版のダブルバトル画面（相手 2 体・自分 2 体）に合わせてあります。
> Switch 版や画面の比率が違う場合は、実際の画面に合わせて調整してください。
> すでに `config.json` がある場合は初期値が反映されないので、`config.json` を削除して起動し直すと初期値に戻ります（OBS のパスワード等は再設定が必要）。

### 2. OBS にオーバーレイを追加

OBS で **ソース追加 → ブラウザ**：

| 項目 | 値 |
|---|---|
| URL | `http://127.0.0.1:8765/overlay` |
| 幅 / 高さ | 320 × 1010（横並び `layout=row` なら 630 × 510） |

URL パラメータで表示を変えられます（`?` の後に `&` でつなぐ）：

| パラメータ | 例 | 内容 |
|---|---|---|
| `slot` | `slot=opp1` | 特定の領域だけ表示（相手ごとに別ソースにして配置できる） |
| `layout` | `layout=row` | カードを横並び |
| `moves` / `items` / `abilities` | `moves=4` | 表示件数（既定は 6 / 3 / 3。特性はポケモンごとに最大 3 つなので既定で全部表示。0 で非表示。行数が多いときは 1 行を細くしてカードの大きさを保つ） |
| `sprite` | `sprite=0` | ポケモンの画像を非表示 |
| `stats` | `stats=0` | 種族値を非表示 |
| `nature` | `nature=0` | 性格・能力ポイントを非表示 |
| `natures` / `spreads` | `natures=3&spreads=1` | 性格 / 能力ポイントの表示件数（既定は 2 / 0 = 能力ポイントは非表示） |
| `w` / `h` | `w=320&h=560` | カードの幅・高さを px で固定（はみ出した分は切れる） |

カードの既定の大きさは **1 枚 300×488px**（技 6・持ち物 3・特性 3・性格 2。2 枚縦に並べて 1080px に収まる）。
カードは、データの量（メガシンカの有無、採用率データの有無など）によらず、**常に同じ大きさ**になります
（足りない行は空欄で場所を確保）。相手が場にいない枠も見えないカードで場所を確保するので、カードの位置もずれません。
大きさは表示件数（`moves` など）と `scale` で決まり、`w` / `h` で直接指定することもできます。

カードには上から「種族値」「技」「持ち物」「特性」「最も多い型（性格・能力ポイント）」を表示します。

- **種族値**: PokeAPI のデータ。メガシンカ後はメガシンカ後の種族値に切り替わります
- **性格**: 性格の採用率を表示します（能力ポイント配分も `spreads=2` で表示可能）。
  取得元を Pikalytics にした場合、ダブルには性格データがありません（シングルは「最も多い型」1 つのみ）
| `scale` | `scale=1.3` | 拡大率 |
| `theme` | `theme=light` | 明るい配色 |

例: `http://127.0.0.1:8765/overlay?slot=opp1&moves=6&scale=1.2`

### 3. 選出画面の読み取り

選出画面（「4匹 選出してください」の画面）を自動で認識します。

- **自分のパーティ**: 左側の名前を文字認識して自動登録します
- **相手のパーティ**: 右側のアイコンを、登録済みのアイコン画像と照合します。
  相手側には名前が出ないため、**初めて見るポケモンは「?」になる**ので、設定画面の「相手のパーティ」で名前を入れて登録してください。
  ゲームのアイコンは毎回同じ絵なので、一度登録すれば次回からは自動で認識されます
- 対戦中に相手の名前を読み取ったとき、選出画面の「?」が残り 1 つだけなら、それがそのポケモンだと判断して自動で登録します
- **画像からの推定**: 採用率データの取得時に、Champions のポケモン画像（選出画面のアイコンと同じ絵。
  [Pokémon Champions Battle Data](https://championsbattledata.com/) の公開画像）を `data/champions_icons` に取得しておき、
  選出画面のアイコンと比べます。はっきり一致したもの（Switch 版の画面では何も学習していない状態で 6 匹中 5 匹）は
  最初の対戦から自動で入ります。色違いなどで色が違う場合は、次のタイプからの推定と組み合わせて判定します
- **タイプからの推定**: アイコンの右のタイプアイコンを読み、未登録のアイコンはタイプの組み合わせから候補を絞ります。
  タイプアイコンは採用率データの取得時にデータ元から 18 種すべて取得する（`data/champions_icons/types`）ので、
  最初の対戦から読めます（データ元のアイコンは丸い形なので、背景の色と白い記号の形で比べます）。
  片方のタイプしか読めなくても、読めた方で絞ります。Champions で使えるポケモンのうち候補が 1 匹だけなら自動で入り
  「推定」（パーティ表示では右上に小さな「?」）と表示され、対戦に出てきたら確定してアイコンも覚えます。
  候補が複数（例: ほのお/ひこう → リザードン・ファイアロー）なら、画像の比較で差がはっきりしていればそれを入れ、
  決まらなければ設定画面に候補のボタンが出るので押せば登録できます。
  選出されずに対戦に出てこなかったポケモンも、これで名前が分かります
- **間違っていたとき**: 設定画面の「相手のパーティ」で、そのポケモンの「修正」を押して正しいポケモンを入力（または候補を選択）。
  パーティが入れ替わり、そのアイコンを正しい名前で覚え直します（間違って登録されていたアイコンは削除）。次の対戦からは正しく認識されます
- 選出画面が出るたびに新しい対戦として自動でリセットされます（「対戦リセット」を押す必要はありません）。
  新しい対戦と判断するのは、①30 秒以上ぶりの選出画面、②対戦画面のあとの選出画面、③相手のアイコンが前の対戦と半分以上違う、
  のどれかのとき。設定画面の上部に「対戦 3 戦目（理由）」のように表示されます

初期の範囲はスマホ版の画面（約 2.17:1）に合わせてあります。画面の比率や余白が違う場合は、設定画面の「選出画面」で
マーカー・相手アイコン（1 匹目と 6 匹目）・自分の名前（1 匹目と 6 匹目）を選んでドラッグし、保存してください。
登録したアイコンは `data/icons` に保存されます。間違えた登録は「登録済みアイコン」から削除できます。

### メガシンカの判定

Champions では、メガシンカしても体力バーの名前は変わりません（例: メガフラエッテも「フラエッテ」）。
そのため、**名前の左にある小さな顔画像の変化**でメガシンカを判定します。

1. 選出画面から見ている対戦で、ポケモンが場に出た直後の顔画像を、そのポケモンの「通常」の姿として覚えます
2. 顔画像が通常と違ってきたら、Champions の画像（通常の姿・メガシンカ後の姿）と比べ、メガシンカ後の姿の方が
   はっきり近い状態が 4 回続いたときだけメガシンカと判断します（状態異常のマークや光で見た目が変わっただけでは判断しない）。
   メガシンカ先が複数（リザードン X/Y 等）でも、画像で近い方を選びます
3. メガシンカは 1 回の対戦で 1 人 1 匹までなので、メガシンカしたポケモンが出た後は、同じ側の他のポケモンはメガシンカ扱いにしません
4. 判定したメガシンカ後の顔画像は覚え、次回から即座に判定します。違っていたら設定画面の「手動で選ぶ」で正しい姿を選んでください

メガシンカ後は、カードとパーティ表示の名前・画像がメガシンカ後の姿になり、特性はメガシンカ後のものに確定します。
採用率（技・持ち物）は元のポケモンのデータをそのまま表示します（メガストーンを持った型として集計されているため）。
メガシンカ前は、カードに「メガシンカ率」（メガストーンの採用率）を表示します。

> 途中から起動した対戦では、すでにメガシンカ後の姿を「通常」と覚えてしまわないよう、覚える処理をしません。
> 覚えた顔画像は `data/portraits` に保存され、設定画面の「登録済みアイコン」（「顔」の印）から削除できます。

### Switch 版 / スマホ版の切り替え

設定画面の「読み取り範囲」の上の「ゲーム」で **Switch 版** / **スマホ版** を選び、「この画面用の範囲にする」を押すと、
読み取り範囲がそのゲーム画面用の初期値に切り替わります（Switch 版は 1920×1080 の画面で計測）。

スマホ版は機種によって画面の端の余白が違い、対戦画面の名前欄の位置がずれます。
初期値には 2 種類の配置（端に余白がある機種・無い機種）が入っていて、名前が読めない欄があると、もう片方の配置でも読んでみて自動で切り替えます。
どちらにも合わない機種は「今の画面から自動で合わせる」を使ってください。

### ニックネーム

ポケモン名の代わりにニックネームが表示されることがあります。

- **自分のポケモン**: 選出画面で名前の右の絵を Champions のポケモン画像と比べ、はっきり分かればそのニックネームを
  自動で登録します（色違いでも輪郭で判定。設定画面の「ニックネーム」に「自動」と表示。違っていたら × で消してください）。
  決まらなかったものは「未登録」として候補のボタンが出るので、押すか入力してください。
  一度登録すれば、以後は選出画面・対戦画面とも自動で認識します（性別は ♀/♂ マークで判定）
- **相手のポケモン**: ニックネームで出てきたときは、名前の横の顔画像で判定します。
  以前に名前で認識して覚えた顔画像か、選出画面で相手のパーティが 6 匹とも分かっていれば、その 6 匹の Champions の画像と比べます
- 判定できなかったときは「現在の表示」の「手動で選ぶ」で選ぶと、そのニックネームと顔画像を覚えます
- ポケモン名と同じニックネーム（例: 「ボチ」）は、そのポケモンとして扱われます
- 登録したニックネームは `data/nicknames.json` に保存され、設定画面から削除できます

### 性別で違うポケモン（イエッサン等）

イエッサン・イダイトウ・ニャオニクスなどは、オスとメスで種族値・特性・技が違い、採用率データも別になっています。
名前の右の性別マーク（赤丸に♀ / 青丸に♂）の色を見て、対戦画面・選出画面とも自動でオス/メスのデータを選びます。
マークの位置がずれている場合は、設定画面の領域一覧で「性別」を選んでドラッグしてください。

カエンジシ・ガブリアス・カバルドンなど、データは同じで**見た目だけオス・メスが違う**ポケモンは、♀ マークならメスの姿の画像
（PokeAPI のポケモン HOME のメスの画像）で表示します（名前はそのまま。採用率・種族値は共通）。

### 4. パーティ表示を追加（任意）

OBS で別のブラウザソースを追加：

| 項目 | 値 |
|---|---|
| URL | `http://127.0.0.1:8765/party` |
| 幅 / 高さ | 1200 × 170（自分が左・相手が右。上下に並べる `arrange=column` なら 600 × 330） |

- 自分・相手とも選出画面から自動で入ります。設定画面から手動で編集することもできます
- 未登録の相手アイコンは、ゲーム画面から切り出した画像のまま表示されます
- いま場に出ているポケモンは枠が光ります（自分側も光らせたい場合は、領域一覧で自分のポケモン名の範囲を追加し「自分」に設定）
- メガシンカは `メガリザードンY` のように入力するとメガシンカ後の画像になります

| パラメータ | 例 | 内容 |
|---|---|---|
| `side` | `side=opp` | `me`（自分だけ）/ `opp`（相手だけ）/ `both`（既定） |
| `layout` | `layout=column` | 縦一列（画面の端に置く用） |
| `arrange` | `arrange=column` | 自分と相手のパーティを上下に並べる（既定は左右: 自分が左端・相手が右端） |
| `size` | `size=64` | 画像の大きさ（px、既定 80） |
| `names` / `label` | `names=0` | 名前 / 「自分」「相手」見出しを非表示 |

画像は初回表示時にインターネットから取得し、`data/sprites` に保存して以後はそれを使います。

### フォントの変更

**設定画面の「フォント」**で選んで「保存して反映」を押すと、カード・パーティ表示の両方に反映されます
（OBS 側の URL の変更や再読み込みは不要）。見本の表示で、保存前に見た目を確認できます。

ソースごとに別のフォントにしたい場合は、URL の末尾にパラメータを付けると、設定画面の指定より優先されます。

| 方法 | 例 | 説明 |
|---|---|---|
| PC のフォント | `font=メイリオ` | PC にインストールされているフォント名をそのまま指定 |
| Google Fonts | `gfont=M PLUS Rounded 1c` | [Google Fonts](https://fonts.google.com/?subset=japanese) の日本語フォントをインストールなしで使える（要インターネット） |
| フォントファイル | `fontfile=MyFont.ttf` | `web/fonts` フォルダに置いた .ttf / .otf / .woff2 を使う |
| 太さ | `fontweight=500` | 100〜900（見出しは自動で太字） |

例: `http://127.0.0.1:8765/overlay?gfont=M PLUS Rounded 1c`

Google Fonts のおすすめ: `M PLUS Rounded 1c`（丸ゴシック）、`Zen Maru Gothic`（丸ゴシック）、
`Dela Gothic One`（極太）、`DotGothic16`（ドット風）。
指定したフォントが見つからない場合は、既定のフォント（BIZ UDPゴシック等）で表示されます。
配信でフォントを使う場合のライセンスは、各フォントの配布元で確認してください（Google Fonts は配信での利用可）。

### 配置例（キャンバス 1920×1080）

スマホ版の画面（横長の約 2.17:1）:

| ソース | 位置 | 大きさ | URL |
|---|---|---|---|
| ゲーム映像 | 0, 0 | 1570×732 | （キャプチャ） |
| 採用率カード | 1572, 6 | 348×1074 | `/overlay?w=318&scale=1.04` |
| パーティ | 0, 800 | 1570×280 | `/party?scale=1.3` |

Switch 版の画面（16:9）:

| ソース | 位置 | 大きさ | URL |
|---|---|---|---|
| ゲーム映像 | 0, 0 | 1440×810 | （キャプチャ） |
| 採用率カード | 1442, 6 | 478×1074 | `/overlay?w=430&scale=1.05` |
| パーティ | 0, 850 | 1440×230 | `/party?scale=1.15` |

> 大きさは OBS のソースのプロパティ（幅・高さ）で決め、四隅をドラッグして拡大しないでください（文字が滲みます）。
> キャンバスが 1920×1080 でない場合は、ソースの大きさと `scale` を同じ比率で変えてください。

### 5. 対戦中

- 相手が出てくると自動で切り替わります（2 回連続で同じ名前を読んだら確定）
- 誤認識したときは設定画面の「手動で選ぶ」に名前を入れて切り替え
- 選出画面で自動リセットされます。手動で消したいときは「対戦リセット」

## 負荷の確認と GPU の利用

設定画面の上部に、負荷が表示されます。

| 表示 | 意味 |
|---|---|
| 処理時間 `取得 / 認識` ms | 画面取得と文字認識に 1 回あたりかかった時間 |
| CPU % | このプログラム全体の CPU 使用率（PC 全体に対する割合。タスクマネージャーと同じ基準） |

読み取りは 0.5 秒に 1 回、名前の部分の小さい画像を読むだけなので、通常は CPU のままで問題ありません。
**CPU が数 % を超えて配信に影響しているとき**は、GPU で動く RapidOCR に切り替えられます。

1. `setup_gpu.bat` を実行（RapidOCR と ONNX Runtime DirectML をインストール。NVIDIA / AMD / Intel の GPU に対応）
2. `config.json` の `ocr` を次のように変更して `start.bat` を再起動

   ```json
   "ocr": {"backend": "rapidocr", "device": "dml"},
   ```

3. 設定画面の OCR 欄が `RapidOCR (GPU: DirectML)` になっていれば GPU で動いています。
   `RapidOCR (CPU)` と出る場合は GPU が使えず CPU で動いています

RapidOCR は CPU でも動きます（`"device": "cpu"`）。Windows 標準 OCR で読み取りが不安定な場合の代替にもなります。
NVIDIA の GPU で CUDA を使う場合は `onnxruntime-gpu` と CUDA / cuDNN を入れて `"device": "cuda"` にします（通常は DirectML で十分です）。

> 参考（開発環境の 4 コア CPU・2 体分を 0.5 秒ごとに読み取り）: RapidOCR の CPU 実行で 1 回約 40ms、CPU 使用率 約 2%。
> GPU に回すとこの分の CPU は空きますが、画像が小さいため処理時間自体はあまり変わりません。

## 採用率データの更新

採用率は [Pokémon Champions Battle Data](https://championsbattledata.com/) の公開 API から取得します（既定）。
ランクバトルのバトルデータ（技・持ち物・特性・**性格**・**能力ポイント配分**の上位 10 件）で、毎日更新されています。
日本語名は [PokeAPI](https://pokeapi.co/) のデータで変換しています。
同 API の[利用規約](https://championsbattledata.com/api-rules/)に従い、オーバーレイ下部に出典を表示しています（表示を消さないでください）。

**起動時に自動で取得します**: `start.bat` で起動すると、データ元が更新されていれば裏で最新データを取得し（使用率上位 100 匹、1 分ほど）、
取得できたらそのままカードに反映します。取得中・取得できなかったときは前のデータで動きます。
起動中にデータ元が更新されても取り直さないので、新しいデータを使うときは起動し直してください。

手動で取得するときは `update_usage.bat` をダブルクリックします。起動中なら設定画面の「採用率データ再読込」で反映されます。
起動時の取得を止めるには `config.json` の `usage.auto_update` を `false` にします（または `start.bat --no-update`）。

データ元に負荷をかけないよう、**取得済みのデータからデータ元が更新されていなければ取得しません**。
データ元の順位の一覧（約 30KB）だけを見て、データの作成日時が前回取得したものと同じなら、何もせずに終了します。
データ元の更新時刻は日によって違う（実測: 13:40 頃の日、18:17 と 21:02 の 2 回更新された日があった）ため、決まった時刻では区切りません。
形式（Doubles / Singles）やデータ元を変えた場合は取得します。どうしても取り直したいときは `update_usage.bat --force`。
Pikalytics はデータの作成日時が分からないので、毎日 `config.json` の `usage.update_hour_utc`（UTC の時。既定 5 = 日本時間 14:00）を区切りにします。

`config.json` の `usage` で取得元を変えられます。

| 設定 | 内容 |
|---|---|
| `"source": "championsbattledata", "format": "Doubles"` | ダブル（既定） |
| `"source": "championsbattledata", "format": "Singles"` | シングル |
| `"source": "pikalytics", "pikalytics_format": "..."` | Pikalytics（性格データなし。フォーマットは `update_usage.bat --source pikalytics --list-formats`） |

> 使用率の「%」はデータ元に無いため、カードには順位だけを表示します。

## 設定項目 (config.json)

| キー | 既定値 | 説明 |
|---|---|---|
| `capture.backend` | `obs` | `obs`（推奨）/ `screen`（デスクトップ直接）/ `file`（画像ファイル・テスト用） |
| `capture.obs.format` | `jpg` | OBS から受け取る画像形式。`jpg` は `png` より軽い |
| `ocr.backend` | `auto` | `auto`（Windows の文字認識 → 使えなければ RapidOCR）/ `windows` / `rapidocr`（GPU 対応）/ `tesseract` |
| `ocr.device` | `dml` | RapidOCR の実行先: `cpu` / `dml`（GPU）/ `cuda` |
| `ocr.threads` | `1` | RapidOCR を CPU で動かすときのスレッド数（1 が最も低負荷） |
| `ocr.scale` | 自動 | OCR 前の拡大率（Windows OCR は 2、RapidOCR は 1）。小さい文字が読めないときに調整 |
| `interval_sec` | `0.5` | 読み取り間隔（秒） |
| `confirm_frames` | `2` | 同じ名前を何回連続で読んだら切り替えるか |
| `min_ratio` | `0.72` | あいまい一致の閾値。誤認識が多ければ上げる |
| `server.port` | `8765` | Web サーバーのポート |

## うまくいかないとき

選出画面の読み取りがうまくいかないときは、選出画面を表示した状態で設定画面の「選出画面」の欄を見てください。
「選出画面の判定」「マーカーの文字」「自分の名前」「相手アイコン」の読み取り結果が出るので、どこで失敗しているか分かります。
スマホ版 / Switch 版の設定が画面と合っていない場合は、選出画面で自動的に切り替わります。

| 症状 | 対処 |
|---|---|
| 「選出画面ではない」のまま | 「マーカーの文字」が「4匹 選出してください」の行になっているか確認。ずれていたら「マーカー」をドラッグで合わせる。場所が合っていても文字が読めない場合は、選出画面を表示した状態で「今の画面を選出画面として覚える」を押すと、以後はマーカーの画像で判定します（文字が一度読めたときも自動で覚えます） |
| OBS の表示が古いまま | ツールを更新したら `start.bat` を起動し直してください（OBS 側のページは自動で読み込み直されます）。それでも変わらなければ、OBS のソースのプロパティの「現在のページのキャッシュを更新」 |
| ポケモンの画像が「?」のまま | 画像は初回だけインターネットから取得します。取得できないと黒い画面に警告が出ます。接続が戻れば自動で表示されます |
| 設定画面に「エラー: ...connect...」 | OBS が起動しているか、WebSocket が有効か、ポート・パスワードが合っているか |
| 「ソースが見つからない」系のエラー | `config.json` の `source` を OBS のソース名と完全に一致させる |
| 「Windows の文字認識が使えないため RapidOCR を使います」 | そのままで問題なし（RapidOCR で動作）。Windows の文字認識を使いたい場合は「文字認識の確認」参照 |
| OCR 結果が空・でたらめ | 「今の画面から自動で合わせる」を押す / 範囲を名前の文字に合わせ直す / `ocr.scale` を 3 にする |
| 自動調整で「見つかりませんでした」 | 選出画面は「選出してください」が表示されている間に、対戦画面は名前欄が 4 つとも見えている間（技を選ぶ画面など）に押してください |
| 採用率データがありません | そのポケモンが上位 50 匹に入っていない。手動で `data/usage.json` に追加可能 |

## 制限事項

- Pokémon Champions の画面レイアウトは実機で検証していません。読み取り範囲は各自で合わせてください
- メガシンカなどのフォルム違いは「種族名」で判定し、データ上で最も使用率の高いフォルムを表示します。
  別フォルムを表示したいときは手動で選んでください
- 採用率データは非公式の集計で、ゲーム内の「バトルデータ」と数値が異なる場合や、取得時点より古い場合があります

## 開発者向け

```
main.py               起動スクリプト
overlay/capture.py    画面取得 (OBS / screen / file)
overlay/ocr.py        OCR (Windows.Media.Ocr / RapidOCR / Tesseract)
overlay/names.py      日本語名辞書・あいまい一致・Showdown 名 → 日本語
overlay/icons.py      画像照合 (選出画面のアイコン / メガシンカ判定の顔画像。正規化相互相関)
overlay/recognizer.py 認識ループと共有状態 (選出画面 / 対戦中)
overlay/autofit.py    読み取り範囲の自動調整 (目印の位置・パネルの形の照合)
overlay/server.py     HTTP サーバー (/overlay, /control, /api/*)
web/                  オーバーレイと設定画面
tools/build_names.py  data/names.json の再生成 (PokeAPI)
tools/update_usage.py 採用率データの取得 (Pokémon Champions Battle Data / Pikalytics)
tools/make_fit_templates.py  自動調整に使うパネルの見本 (data/fit) の作成
```

テスト: `python -m unittest discover -s tests -t .`

Windows 以外で動作確認する場合は Tesseract（`jpn` 言語データ）を入れ、`ocr.backend` を `tesseract` にしてください。
